# BUG-14: Байхгүй номыг (DELETE /api/books/999) устгахад 404 биш «200 OK» буцаадаг

Орчин:  Уншлагын жагсаалт v2.0, Chromium 153 (Firefox 155-д мөн давтагдсан), Windows 11 Pro, 2026-10-15

Урьдчилсан нөхцөл: node app.js-ийг шинээр асаасан (анхны 3 ном)

## Дахин гаргах алхам
1. Терминалд: `curl -i -X DELETE localhost:3000/api/books/999`
2. `curl -i -X DELETE localhost:3000/api/books/2`
3. Ижил командыг дахин: `curl -i -X DELETE localhost:3000/api/books/2`
4. `curl -i localhost:3000/api/books`

Хүлээгдэж байсан: Эрүүл ухаан (REST): байхгүй нөөцийг устгах хүсэлтэд `404 Not Found`
                  (апп өөрөө бусад байхгүй замд `404 {"result":"ERROR_NOT_FOUND"}` өгдөг).

Бодит үр дүн:     1-р алхамд `HTTP/1.1 200 OK` `{"result":"OK"}`; 2-р алхам зөв устгана; 3-р
                  алхамд аль хэдийн устгагдсан id 2 дахин `200 OK {"result":"OK"}`. 4-р алхамд
                  id 2 байхгүй. GUI-д: хоёр таб нээж нэгээс нь ном устгаад нөгөө (хуучирсан)
                  табаас ижил номын «Устгах» дарахад ямар ч алдаа гарахгүй.

Ноцтой байдал: Minor — өгөгдөл эвдэхгүй, гэвч клиент "устгасан" гэж худал ойлгож, буруу id-ийн
               алдааг илрүүлэх боломжгүй.
